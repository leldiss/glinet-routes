# Домены и сети для раздельной маршрутизации GL.iNet

Файл `routes.txt` содержит домены и IPv4-подсети по одной записи на строку. GitHub Actions пересобирает файл ежедневно и при изменении исключений. При ошибке загрузки или проверки сохраняется ранее опубликованная версия.

## Источники

- Домены сервисов для пользователей в РФ — [itdoginfo/allow-domains, Russia inside](https://github.com/itdoginfo/allow-domains).
- Домены и IPv4-сети Telegram — [marcomc/glinet-vpn-subscription-lists](https://github.com/marcomc/glinet-vpn-subscription-lists). [Сведения об источниках данных и лицензиях](https://github.com/marcomc/glinet-vpn-subscription-lists/blob/main/DATA-LICENSES.md).

В `vpn.txt` перечислены дополнительные домены сайта и плеера Twitch, видеосегментов, оформления Speedtest и серверов Ookla. Выбранный Speedtest сервер оператора на собственном домене может использовать прямой маршрут.

Для магазина Steam и мастерской в список включены веб-страницы, домены стилей, скриптов и превью модов. Совпадение по `steamcommunity.com` распространяется на все разделы сообщества Steam.

Сборка удаляет дубликаты и пропускает запись `.ua`, которая направила бы в VPN целую доменную зону. В `direct.txt` перечислены исключённые домены игр и сервиса 2IP. Можно добавить туда домены своих игр. Исключение срабатывает для указанных имён и их поддоменов в исходных списках. Совпадение с общей подсетью или более широким доменом всё ещё может направить трафик в VPN.

## Настройка

Опубликуйте файлы в отдельном публичном репозитории GitHub на ветке `main`. Включите GitHub Actions. Откройте `routes.txt` на GitHub и скопируйте адрес кнопки **Raw**. В панели GL.iNet выберите немецкий профиль, нужный клиент и **Specified Domain / IP List → Subscription URL**. Вставьте адрес, нажмите **Detect** и **Apply All Changes**. Для игрового ПК оставьте включённым **Allow Non-VPN Traffic** и исключите ПК из других общих правил VPN. Для доменных правил используйте DNS роутера на этом ПК.

Локально сборка запускается командой `pwsh -File update.ps1` в PowerShell 7. Для ручной проверки в GL.iNet можно вставить содержимое готового `routes.txt` в режиме **Manual**.

## Подписка по исходным правилам Xray

[Подписка Xray для GL.iNet](https://raw.githubusercontent.com/leldiss/glinet-routes/main/routes-xray.txt). Для перехода замените URL в существующем туннеле. Для возврата используйте [прежнюю подписку](https://raw.githubusercontent.com/leldiss/glinet-routes/main/routes.txt).

В подписке Xray действуют два явных правила для `anthropic.com` и `claude.ai` и следующие категории из одной ревизии открытой базы Runet Freedom. Файлы `vpn.txt` и `direct.txt` относятся к прежней подписке. [Источник категорий](https://github.com/runetfreedom/russia-v2ray-rules-dat)

- Домены из `ru-blocked`, `youtube`, `meta`, `twitter`, `openai`, `discord`, `telegram` и `whatsapp`.
- IPv4-сети из `re-filter`, `ru-blocked` и `ru-blocked-community`. Пересекающиеся диапазоны объединяются с сохранением точного множества адресов. Из него вычитаются служебные сети категории `private`, для которых в исходной конфигурации действует более приоритетное правило блокировки.

GL.iNet сопоставляет соединения по назначению. Игровой сервер с адресом внутри одной из перечисленных сетей также попадёт в VPN. Для остальных адресов действует обычная политика роутера. В текстовом файле представлены доменные имена и IPv4. Регулярные выражения, поиск по части имени, целые доменные зоны, IPv6, правила по портам и протоколам, блокировка и переключение выходов Xray в этот формат не перенесены. Точное имя из Xray записывается в формате обычного домена GL.iNet. [Формат подписки GL.iNet](https://docs.gl-inet.com/router/en/4/tutorials/how_to_configure_domain_and_ip_filtering_rules_for_glinet_routers_via_an_online_text_file/)

Для локальной пересборки этой подписки запустите `python update_xray.py --sing-box <путь-к-sing-box>`. Протестировано с sing-box 1.14.4 и Python 3.12.

## Видеоплеер Twitch через VPN, BongaCams и XVideos напрямую

[Адрес тестовой подписки](https://raw.githubusercontent.com/leldiss/glinet-routes/main/routes-xray-twitch.txt). Для проверки замените URL в том же туннеле и оставьте **Allow Non-VPN Traffic** включённым.

При каждой сборке к списку Xray добавляются домены Twitch и конкретные узлы CloudFront из категории `twitch`, а также имена серверов и DNS-псевдонимы, замеченные при воспроизведении эфира и записи. Для общего сервиса Amazon IVS включены домены, используемые плеером Twitch. [Источник категории Twitch](https://github.com/v2fly/domain-list-community/blob/master/data/twitch)

Пять отдельных IPv4-адресов служат дополнительными правилами для плейлистов и видеосегментов, к которым трафик с MT6000 шёл через провайдера. Другой сервис на таком же IP тоже может попасть в VPN. При смене регионального узла Twitch основой маршрутизации остаются домены.

Домены BongaCams и XVideos, известные зеркала и CDN исключены. При каждой сборке из VPN-подсетей вычитаются конкретные IPv4-адреса этих сайтов по DNS. Сохраняются также проверенные адреса основных узлов из РФ. На общем IP такое исключение может затронуть другие сайты, а новое зеркало или региональный узел CDN может потребовать дополнительной записи.

Вариант пересобирается после ежедневного обновления списка Xray. Локальный запуск — `python -B update_twitch_routes.py`. Для возврата к исходным категориям используйте [чистую подписку Xray](https://raw.githubusercontent.com/leldiss/glinet-routes/main/routes-xray.txt).
